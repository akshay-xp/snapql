# Panel

Solid UI in `src/panel/`: header, request list, detail pane. Reads entries from the capture store; never touches `chrome.*` directly (theme comes through `src/browser/devtools.ts`).

## Layout (`src/panel/app.tsx`)

- No header bar.
- Type: labels (tabs, section headings, buttons, search placeholder, footer count, messages, Timing phase names) in Tailwind `font-sans` at 12px (`text-xs` on `main`); everything from the request is `font-mono`: rows, the Summary heading and meta line, `<pre>` blocks, pairs, JSON trees, token expiry, Timing values.
- Body: flex row, or flex column when stacked (below). Left (top when stacked) `<section>` (`flex-1 flex-col`): `SearchBox`, `FilterChips` (only while the store has entries), then `Waiting` when the store is empty ("Waiting for requests", "Reload the page to capture its traffic.", and a `Reload and capture` text button), else `NoMatches` when the filter hides everything, else `List`; then `Footer`. `Waiting` and `NoMatches` share the centered `Message` layout. `Detail` right (below when stacked) when an entry is selected.
- Stacking: `isStacked(width, height)` (`width < height`, pure) from a `ResizeObserver` on the row (applied next frame, see below). A side-docked DevTools (tall) stacks list over detail; bottom-docked (wide) puts them side by side, like DevTools' own auto panel layout.
- Footer (`src/panel/footer.tsx`): icon buttons, each with `aria-label` = `title`: Clear; sort (`Newest first` / `Oldest first`, the current order, icon flips); Preserve log (`aria-pressed`); Reload and capture (reloads with the probe injected first, see `docs/capture.md`). Every button carries a visible `caption` (`Clear`, `Newest` / `Oldest`, `Preserve`, `Reload`, `Schemas`, `Export`), rendered by `IconButton` as `<span data-caption>`. The footer is an `@container` and hides `[data-caption]` below `32rem` (a narrow side-by-side list), leaving icons and tooltips; the count is `min-w-0 truncate`, so a 200px list never overflows. A pressed `IconButton` is `bg-accent/20 text-accent`. The count is `[data-count]`, which e2e reads instead of the whole footer text. Schemas (`aria-pressed` while open): toggles the schema popover (below). Export HAR (`aria-pressed` while open): toggles the export popover (see HAR export). Then the count, `count(n, "request")` (`0 requests`, `1 request`), or `<shown> of <total>` while a query is set (`total` prop given only then). Icons inline SVG, `aria-hidden`.
- Divider (`src/panel/splitter.tsx`, `src/panel/splitter.ts`): an `<hr aria-orientation>` (implicit `separator` role; Biome prefers the native element) absolutely positioned over the detail pane's left border (`vertical`) or top border (`horizontal`, when stacked), so it takes no layout space and list + detail always fill the row.
  - Drag: `pointerdown` on the handle adds `pointermove`/`pointerup` listeners on `window` (drag survives leaving the handle; also works with the e2e's synthetic events), removed on release or unmount.
  - `App` owns `detailWidth` and `detailHeight` (undefined = 50%, until the first drag in that layout; not persisted); `Detail` gets the one for the current layout as `size`. Width = row's right edge minus pointer x, height = row's bottom minus pointer y, through `clampSize(size, container, MIN_PANE)`: each side keeps at least `MIN_PANE` (200px); a row smaller than 400px splits in half.
  - Pointer only: the handle is not focusable (keyboard resizing not in scope).

## State

- `entries`: Solid signal mirroring `store.snapshot()` on each store notification.
- `selectedId`: signal in `App`. `selected()` derives the entry; an effect resets `selectedId` to `undefined` when the entry leaves the store (Clear, eviction, navigation), which closes the pane.
- `preserveLog`: owned by `main.tsx` (see `docs/capture.md`).
- `query`: signal in `App`, default `""`, not persisted.
- `searchBodies`: signal in `App`, default `false`, not persisted. `bodyVersion` counter bumps on each indexed body so `visible` recomputes.
- `filters` and `hide`: from the active workspace (`props.workspaces`, below); chips filter for as long as they are selected.
- Workspaces (`src/panel/workspaces.ts`): `Workspace = { id, name, filters, hide }`, `Stored = { active, workspaces }`.
  - `parseWorkspaces(text)` (pure): `defaultWorkspaces` (one `Default`: `noFilters`, `defaultHide`) when the text is missing, unparsable or has no non-empty `workspaces` array; a dangling `active` id falls back to the first workspace.
  - `createWorkspaces(storage)`: a `Stored` signal starting at `defaultWorkspaces`, replaced once `storage.load()` resolves (`ready`). `name()`, `filters()` and `hide()` read the active workspace; `setFilters`/`setHide` rewrite it and `save` the whole set as JSON immediately (no Save step; a throwing `save` is ignored).
  - `WorkspaceStorage = { load(): Promise<string | undefined>; save(text) }`: async so `chrome.storage.sync` can replace `localStorage` later without a permission today. `localWorkspaces(kv)` stores under `snapql.workspaces`, swallowing storage errors; `main.tsx` passes the same `localStorage` handle as schemas.
- `visible`: `createMemo` in `App`: entries filtered by `matchesQuery` and `matchesFilters(e, active)`, then reversed when `newestFirst`. `List`, `Footer`, the no-match check and `selected()` all read it.
- `newestFirst`: signal in `App`, default `true`, not persisted. `App` passes `List` the reversed list when on; `List` knows nothing of order, so ↑/↓/Home/End follow the displayed order.

## List (`src/panel/list.tsx`, `src/panel/virtual-listbox.tsx`, `src/panel/keys.ts`)

- `VirtualListbox<T>({ items, key, selected, onSelect, label, idPrefix, children(item, selected) })` owns everything below except row contents: listbox ARIA, virtualization, keys, the `h-7` `role="option"` row wrapper. Used by the request list (`Requests`, `entry-`) and Messages (`Messages`, `message-`).

- `role="listbox"`, `tabIndex=0`, holds focus; rows are `role="option"` with `id="entry-<id>"` and `aria-selected`. The listbox's `aria-activedescendant` points at the selected row, so focus never moves to rows (survives virtualization later). Rows are therefore not focusable and have no key handlers (two Biome a11y rules suppressed with that reason).
- Row: 28px (`h-7`), parts from `rowLabel(entry)` (`src/panel/row.ts`, pure), in order: title (`flex-1 truncate`, URL tooltip), detail, failure pill, `live` tag, message count, kind tag. Only the title and detail shrink: detail is `min-w-0 max-w-1/2 truncate` with a tooltip (socket subprotocols can be long tokens), so the title keeps half the row and the listbox never scrolls sideways.
  - Decoded: the decoder's `title`, `detail`, `kind`. Undecoded: title = path + query (repeated calls to one endpoint stay distinguishable), detail = method, no kind.
  - `failure`: status code when `>= 400`, `failed` when status is 0; pill `bg-error text-bg` (no extra token, passes contrast). No method/status columns.
  - `live`: open streams (`entry.open`), in `text-accent` (plain on the selected row).
  - `closed`: `closed <code>` for a closed socket (muted), where `live` was.
  - `count`: `<n> msgs` (muted) only when the entry has `messages` (live streams, sockets). Finished-body streams show none: counting them would load every body.
  - Kind tag `w-[11ch]` (fits the longest kind, `multipart`, in mono), bordered; rendered empty with a transparent border when undecoded so tags align in a column.
  - Selected row `bg-selected`; detail and tag drop `text-muted` there (muted on `selected` is under 4.5:1 in both themes).
- Virtualized (`src/panel/virtual.ts`), no library. The listbox is the scroll container holding a spacer `div` of height `count * ROW_HEIGHT`; the rendered slice `[start, end)` sits in an inner `div` with `translateY(start * ROW_HEIGHT)`.
  - `ROW_HEIGHT = 28` in `virtual-listbox.tsx` must match the rows' `h-7` (border-box, border included). Overscan 10 rows each side.
  - `visibleRange(scrollTop, viewportHeight, rowHeight, count, overscan)` (pure): `start = max(0, floor(scrollTop/rowHeight) - overscan)`, `end = min(count, ceil((scrollTop+viewportHeight)/rowHeight) + overscan)`.
  - `scrollTop` comes from `onScroll`, viewport height from a `ResizeObserver` on the listbox (disconnected on cleanup). Both observers set state in `requestAnimationFrame`: relaying out inside the callback (a new scrollbar, a stack flip) raises "ResizeObserver loop completed with undelivered notifications".
  - Keyboard moves call `scrollToRow(index, scrollTop, viewportHeight, rowHeight)` (pure: new `scrollTop` aligning the row's top or bottom edge, or `undefined` if fully visible) and set `scrollTop`, so the selected row is rendered and `aria-activedescendant` always resolves.
- Keys (`nextIndex(key, current, count)`, pure): ↑/↓ move and clamp; ↓ with no selection selects the first row, ↑ the last; Home/End jump; empty list or other keys do nothing. Moving selects (like the Network panel), so there is no Enter. Esc deselects (closes the pane). Click selects.

## Search (`src/panel/search.tsx`, `src/panel/filter.ts`)

- `SearchBox`: `h-10` `<search>` bar atop the list (same height as the tab bar, so they line up side by side); `<input type="search" aria-label="Filter requests">` (native cancel button hidden) inside a `surface` pill with an accent focus ring; × `IconButton` (`Clear filter`) only while the query is non-empty.
- `matchesQuery(entry, query, bodyText?)` (pure): case-insensitive substring over what the row shows (`rowLabel` title, detail, kind) plus the full URL, plus `bodyText` when given; empty query matches all. Decoded rows don't show their method, so `POST` doesn't match a GraphQL row.
- Search bodies: an `Include bodies` `Pill` (`title="Also match text inside request and response bodies. Matches show an excerpt in the list."`, `ring-1 ring-inset ring-border` so it reads as a button on the `surface` box; chips don't get the ring) inside the search box, before ×. While on, the placeholder reads `Filter requests and bodies` (`aria-label` stays `Filter requests`) and `App` passes the joined request and response text to `matchesQuery`.
  - Body-only rows: `App.hitOf(entry)` gives `bodyHit(bodies.text(e), query)` when body search is on and `matchesQuery` without body text fails. `List` then shows a muted `min-w-0 truncate` `<side> (<count>): <excerpt>` (highlighted) in place of the detail, so the row stays one line. Rows matching on title, detail, kind or URL keep their detail.
  - `bodyHit(texts, query)` (pure, `filter.ts`): `{ side, count, excerpt }` for the response when it matches, else the request, else `undefined`; `count` is the `highlight` hits on that side only.
  - `excerpt(text, query)` (pure, `filter.ts`): whitespace collapsed, first case-insensitive match with 20 chars before and 60 after, `…` on each cut side; `undefined` without a match.
  - Open where it matched: `App.select` wraps `List.onSelect`; for a row with a `bodyHit` it sets `openTab` to a fresh `{ tab }` (`Body` for response, `Raw` for request, the only tab showing the request body), otherwise clears it. `Detail` applies it to `active` in an effect. Arrow keys go through the same path.
  - Body and Raw tabs: `Detail.bodyQuery` (`searchBodies() ? query() : ""`, so plain row filtering never expands trees) flows to `BodyView` (`JsonTree` and `Text` take `query`) and `RawView` (both `Text`s). Keys and leaves render through `Marked`; containers where `hasMatch(value, query)` open, and return to `startsOpen` when the query clears; a string whose match lies past `STRING_LIMIT` shows in full. Raw counts header matches too.
  - Stepping (`src/panel/matches.tsx`): `createMatches(root, deps, step)` collects `root`'s `mark`s a microtask after `deps` change (so tree nodes opened by their own effects count) and resets to the first; `move(by)` wraps; the current mark alone gets `data-current` (`bg-accent text-bg` via `Marked`'s `data-current:` classes) and `scrollIntoView({ block: "center" })`. `BodyView` and `RawView` each wrap their content in a `contents` div ref and put `MatchNav` (`[data-match-nav]` `Match n of m`, `Previous match (Shift+Enter)` / `Next match (Enter)` `IconButton`s, the keys in the tooltip; hidden at 0) first in the `Toolbar`. `Toolbar` is `sticky -top-3` (cancelling the tabpanel's `p-3`) with `bg-bg` and `-mx-3 px-3`, so Copy, Expand all and stepping stay visible over long bodies. Enter / Shift+Enter in the search input call `SearchBox.onStep(±1)`; `App` keeps `stepMatch` as a fresh `{ by }` per press, passed through `Detail` into `createMatches` (deferred, so a tab opened later ignores old presses). Changing tab remounts the view; changing query or request changes `deps`.
  - `hasMatch(value, query)` (pure, `json.ts`): case-insensitive, true when any key or leaf (`String(value)`) at any depth includes the query; empty query is false.
  - `createBodyIndex(onChange)` (`src/panel/body-index.ts`, Solid-free): `sync(entries, on)` (an `App` effect) starts `loadBody(entry, { pretty: false })` once per unseen `getBody`; `text(entry)` gives `BodyTexts` `{ request, response }` (response `""` for `view` bodies: image, font, hex; rejected bodies give `""` via `loadBody`), `undefined` until resolved; `onChange` after each.
  - Keyed by `getBody` in a `WeakMap`: `appendMessages` copies keep it (live entries not refetched); the finished merge brings a new one (a live fetch is reindexed once complete); freed with the entries.
  - Off: no new fetches, matching ignores the index; the cache is kept, so turning it back on is instant.
- `highlight(text, query)` (pure): `{ text, hit }` segments, every occurrence, original casing, query matched literally (`indexOf`, no regex). `Marked` renders hits as `<mark>` (`bg-accent/30`); `List` passes title and detail through it.
- Filters (`FilterChips`): an `h-8` row (`border-b`) under `SearchBox`: a `<fieldset aria-label="Filters">` (`flex-1`, scrolls horizontally, no wrap) with kind chips, a `w-px` separator and status chips, then `HideMenu` pinned outside the scroll (a popover inside it would be clipped). Chips are `Pill`s (`search.tsx`): mono `rounded-full` buttons with `aria-pressed`, `bg-accent/20 text-accent` when on, `bg-surface` when off.
- Hide (`HideMenu`, `[data-hide]`): button (`aria-haspopup="menu"`, `aria-expanded`) reads `Hide` or `Hide (n)`, pressed colours while n > 0. Popover `[data-hide-menu]` (`role="menu"`, Schemas popover style, `top-full right-0`): checkboxes `role="menuitemcheckbox"`, `value` = `preflights` / `cached` / `assets`, labelled Preflights, Cached, Static assets (`accent-accent`). Escape inside closes and refocuses the button; a `window` `pointerdown` outside `[data-hide]` closes (listener only while open). `hide` comes from the active workspace, starting at `defaultHide` (all three on: most sessions target the app's own calls).
  - `isHidden(entry, hide)` (pure, `filter.ts`; `Hide = { preflights, cached, assets }`, `noHide` all false): preflights = method `OPTIONS`; cached = `exchange.fromCache` set or status `304`; assets = base mime `image/*`, `font/*`, `video/*`, `audio/*`, `text/css`, `text/javascript`, `application/javascript`, `application/x-javascript`, `application/wasm`. `visible` ANDs `!isHidden` with query and chips, so HAR export follows.
- Pressed states (`Pill`, `IconButton`) set exactly one color class per state through `classList`: with both `text-muted` and `text-accent` present, CSS order decides and muted wins.
  - `chipsFor(entries, selected = noFilters)` (pure): `{ kinds, statuses }` present in the store plus the selected ones, so a saved chip shows (pressed) before its traffic arrives. `kindOf` = `decoded.kind` or `other`; `statusGroup` = `failed` for 0, else `<n>xx`. Alphabetical/ascending, `other`/`failed` last. JSON calls show as `json` (no `rest` kind).
  - `matchesFilters(entry, filters)`: OR within a group, AND across groups, an empty group doesn't constrain. `toggle(filters, group, value)` returns a new object.
- Footer shows `<shown> of <total>` while a query is set, any chip is active, or the Hide toggles hide at least one entry (they are on by default, so `on` alone would always show `n of n`).
- No matches with a query: `No requests match "<q>"` and a `Clear filter` text button (clears the query and the chips); unchanged by workspaces.
- No matches without a query (`WorkspaceHiding`): `<name> is hiding <count(total, "request")>` with text buttons `Show all` and `Clear filters` (`setFilters(noFilters)`, `setHide(noHide)`: everything shows, and that is saved). Text buttons are `TextButton` (`text-accent underline`).
- Show all: session-only `showAll` signal in `App` (off on every panel load). `shownFilters()` / `shownHide()` are `noFilters` / `noHide` while on, else the workspace's; filtering, the footer total, chips and `HideMenu` all read them, so chips and Hide render unpressed. A `[data-showing-all]` accent pill (`Showing all`, before the chips' `fieldset`) turns it off, restoring the workspace untouched. Editing a chip or Hide option while on calls `leaveShowAll()` first: the shown state (`noFilters`, `noHide`) is saved, then the edit applies, so what was on screen plus the edit becomes the workspace.
- When the filter hides the selected entry, `selected()` (looked up in `visible`) becomes `undefined` and the existing effect clears `selectedId`; clearing the query does not reselect it.

## Detail (`src/panel/detail.tsx`, `src/panel/summary.ts`)

- Active tab underlined in `border-accent`. Tabs, in order: Summary, Body, Messages, Headers, Params/Cookies, Timing, Raw. `tabsFor(entry)` (`src/panel/tabs.ts`, pure) gives sockets `Summary, Messages, Headers` (no body, params or timing; Headers holds the handshake Chrome reports after close); otherwise it includes Messages only for a stream mime (`streamParser` exists) or an entry with `messages`; `shownTab(active, tabs)` falls back to Summary when the kept active tab is hidden for the new entry. `role="tablist"`, each tab `aria-selected`/`aria-controls`, id `tab-<slug>` (`Params/Cookies` becomes `params-cookies`); one `role="tabpanel"` for the active tab.
- Spacing: tab bar `h-10` (scrolls horizontally if the tabs don't fit); tabpanel `p-3`, `flex-col gap-4`, so every top-level block (heading, sections, Response group, toolbar) is 16px apart and sections carry no margins. Section: `h-6` heading row, `gap-1.5`, block `px-3 py-2`. Raw shows Request and Response as `Section`s.
- Wrapping: text wraps at spaces first, breaking long tokens only when needed (`overflow-wrap: anywhere`, not `break-all`) in `<pre>`, pairs, JSON trees and the heading title. Pairs key column `fit-content(40%)`, so long keys wrap instead of squeezing values.
- Click switches. ←/→ on the tablist move via `nextTab(key, current, count)` (pure, wraps at both ends, per the WAI-ARIA tabs pattern) and focus the new tab. Only the active tab is in the Tab order (`tabIndex` 0, others -1), so Tab moves list, then active tab, then panel content.
- Headers: request then response headers. Params/Cookies: query params, request cookies, response cookies. Both use `Pairs`; empty sections say "None".
- `Pairs(title, pairs, decode?)`: a `Section` holding `<dl data-section={title}>`, grid `max-content | minmax(0,1fr)`, mono; `<dt>` key in `syntax-key`, `<dd>` with `<span data-value>` (red `text-error` when the section is named `errors`, e.g. GraphQL response errors: a generic rule, no per-decoder UI) and the optional decoded line.
- Timing (`TimingPanel` in `detail.tsx`, model `timingView(timings)` in `src/panel/timing.ts`, pure):
  - `ssl` is never a row or added to the total: HAR already counts it inside `connect`. When measured it shows on the Connect row as `incl. TLS n ms` (`tls`).
  - Rows: measured phases only, in order, each `{ phase, label, stage, ms, offset, fraction }`; `fraction` = ms / sum of measured phases, `offset` = sum of earlier fractions (waterfall). Labels and stages: Queued, DNS lookup, Connect (`setup`); Request sent, Waiting (TTFB) (`server`); Download (`download`).
  - `stages`: per-stage `ms` and `fraction` sums in order (setup, server, download), zero stages dropped; `top` = the stage with the largest fraction. `reused` when dns and connect are both unmeasured.
  - Render, three blocks: `Total` (muted) + `[data-total]` (`text-xl` semibold mono); `[data-stages]` tiles, one `[data-stage]` per stage (swatch, label, mono ms, muted %; `bg-surface`, `min-w-28 flex-1`, wrap), the `top` one marked `data-top` and outlined in its stage colour (others `border-transparent`); then `Section` "Phases": a grid of `[data-phase]` label, `[data-ms]` (mono, muted), and a bar `[data-bar]` (`margin-left` offset, `width` fraction, `min-w-px`), then `Reused connection: no DNS or connect` when `reused`. The `stage` map in `detail.tsx` holds each stage's label, `bg-*` and `border-*` (setup `muted`, server `accent`, download `success`).
- Raw: `rawRequest(entry)` (`METHOD path?query VERSION`, headers, blank line, body) and `rawResponse(entry, body)` (`VERSION STATUS TEXT`, headers, blank line, body); version falls back to `HTTP/1.1`.
- Active tab is a signal in `Detail`; it survives selection changes because the `Show` around `Detail` is not keyed.
- Summary heading (`src/panel/heading.ts`, `src/panel/copy.ts`, `summaryHeading(entry)`, pure): `<header>` with the title (`rowLabel`'s, 15px semibold) and a tag `<kind> <detail>` (absent when undecoded; `min-w-0 max-w-1/2 truncate` with the full tag as tooltip); then a muted meta line `METHOD path · <status> · <ms> ms · HH:MM:SS`.
  - `path` = pathname + search; the full URL is its tooltip (`data-path`, `[overflow-wrap:anywhere]` for long query strings). The host is not shown.
  - `status`: `<code> <statusText>` (trimmed), `failed` for 0, `closed <code>` for a closed socket (`ok` for 1000 and 1005, `cleanClose` in `src/panel/socket.ts`); `data-status` in `success` when `0 < status < 400`, else `error`. Clock is local time from `startedAt`.
- `Section(title, copy?, children)`, `Text`, `Pairs` and `Sections` live in `src/panel/section.tsx` (shared with Messages): `<section>` with a muted semibold `<h2>` and a `data-block` `surface` block. Used by decoded sections, `Pairs` and Tokens (one block per token).
- `dataSections(decoded.data)`: a field holding a non-empty array of `{ name: string, value: string }` becomes a rows section, rendered with `Pairs` (decoders use this for form fields, parts, calls). Other fields become labelled sections: strings as `{ name, text }` (`<pre>`, e.g. GraphQL query text), everything else as `{ name, json }` (`JsonTree`, e.g. variables). Non-object data is one `data` section; `null`/`undefined` none. Protocol-agnostic: no per-decoder UI.
- Socket section (sockets only, before decoded sections): `Pairs` from `socketRows(entry)` (`src/panel/socket.ts`, pure): `protocol` (negotiated, `none`), `frames sent`, `frames received`, then `close code`, `close reason` once known (empty reason omitted).
- Response group: when `decoderFor(decoded.kind, decoders)` has `decodeResponse` (`decoders` imported from `src/decoders/index.ts`), `ResponseGroup` loads `entry.getBody()` (raw `Body`; rejection means nothing renders), skips bodies over `BODY_LIMIT`, and renders a group heading `Response · <summary>` over its `Sections` (the same `dataSections` rendering). Mounted only inside Summary, so the body loads only while Summary is shown for such an entry. Nothing renders when `decodeResponse` returns `undefined`.

## Messages (`src/panel/messages.tsx`, `src/panel/messages.ts`)

- Tab content: an entry with `messages` (live capture) shows them directly, `timed`; otherwise `LoadedBody` (`pretty: false`, so the body loads only while the tab is shown), `parseStream(entry.mimeType, text)`, then `bodyMessages(events, entry.startedAt)` (`dir: "in"`, start time). `Messages({ messages, timed })` lists them in a bordered `VirtualListbox` (`min-h-24 flex-1`).
- Row, mono (offset, event and size drop their muted/syntax color on the selected row, as request rows do): offset `+1.234s` from the first message (only when `timed`: live messages; body-parsed ones share one time), `event` in `syntax-key`, `preview(text)` (whitespace collapsed, CSS-truncated), size muted at the right.
- `directions` (Detail sets it for sockets): a muted `arrow(dir)` (`↑` sent, `↓` received) after the offset. Streams only arrive, so no arrows there.
- Decoded frames: Detail passes `decode` built from the entry's decoder `decodeMessage` (with `entry.messages` as `frames`); `Messages` calls it per rendered row. `frameLabel(m, decoded?)` (pure) gives the decoded title and a muted detail, else `messageText`. The selected decoded frame shows its `data` as a `JsonTree` (raw text when `data` is not an object); Copy still copies the raw frame.
- `messageText(m)`: `binary <size>` for binary frames (`bytes` set), else `preview(text)`; the selected binary frame shows it too.
- Labels (pure): `byteLabel` base 1000 (`999 B`, `1.2 kB`, `1.5 MB`); `messageBytes` = `bytes` (binary frames) or UTF-8 length; `offsetLabel`.
- Selecting (click, ↑/↓) shows `Message <n>` below the list (`max-h-1/2`, scrolls): `Section` with Copy (raw text), `JsonTree` when `treeValue(text)` (`src/panel/json.ts`: JSON object or array, shared with Body) else `Text`. Keyed by message, so a `Copied` state never carries to another message. Detail keys `Messages` by entry id: live updates replace `messages` on every append, so selection resets only when another entry is shown.
- `VirtualListbox` `follow`: when the list was at the bottom (within a row) as items grow, it scrolls to the new bottom; scrolled up, it stays put. Messages sets it.

## Binary frames (`src/panel/binary-frames.ts`, `src/panel/hex-dump.ts`)

- Frames with `base64` decode in the panel (`frameDecoder(entry, format)` in `detail.tsx`); text frames keep the protocol decoder.
- `binaryFormat(protocols)`: negotiated protocol first, then requested; the first containing `msgpack`, `cbor` or `proto` picks `msgpack`, `cbor`, `protobuf`; else `hex`.
- `Decode as` select (`Hex`, `msgpack`, `CBOR`, `protobuf`) above Messages when any frame has bytes; overrides the format for all that entry's binary frames; kept per entry id while the panel is open. Row labels are reactive, so a switch shows at once.
- `decodeBinaryFrame(m, format)`: `hex` gives title `binary <n>`, data the hex dump; a parsing format gives title = compact JSON preview of the value, detail = format, data = the value (tree when selected); a failure gives title `binary <n>`, detail `invalid <format>`, data `<error>\n\n<hex dump>`.
- Selected frame: tree for object/array data, else the decoder's text (dump, error), else the text. Copy gives `base64` for binary frames.
- `hexDump(bytes, limit = 65536)`: 8-digit offset, 16 hex bytes (padded), `|ASCII|` (`.` for non-printable); past `limit`, `… <n> more bytes`.

## JSON tree (`src/panel/json-tree.tsx`, `src/panel/json.ts`)

- `JsonTree(props: { value, openDepth? })`, hand-written, `font-mono`. Used for Summary `json` sections, Tokens header/payload and the Body tab.
- Rules (pure, `json.ts`): `children(value)` (arrays by index, plain objects by entries, else leaf); `startsOpen(depth, openDepth = OPEN_DEPTH)` with `OPEN_DEPTH = 3` (depth >= 3 starts collapsed); `sizeLabel` for collapsed nodes (`{…} 2 keys`, `[…] 1 item`, empty `{}`/`[]`); `brackets` for open ones (`{2}`); `clip(text)` at `STRING_LIMIT = 200`.
- Branch node: caret `<button aria-expanded>` (`▾`/`▸`, `aria-label` = key, or `JSON` at the root), key, `brackets` or `sizeLabel`; children indented `pl-4`. Its `open` signal starts at `startsOpen(depth, openDepth) || hasMatch(value, query)` and resets when either changes (Expand all, body search).
- Leaves: key `data-json="key"` `text-syntax-key`; strings `data-json="string"` `text-syntax-string` (quoted via `JSON.stringify`; clipped ones end `…` plus a `show more` button that reveals the rest); numbers/booleans `data-json="number"` `text-syntax-number`; `null` `data-json="null"` and empty objects/arrays `data-json="empty"`, both muted.
- Body tab (`BodyView`): a right-aligned `Toolbar` with `Expand all` (only when the pretty text parses as an object or array; sets `openDepth` to `Infinity`) and `Copy`, above the tree or `<pre>` text. Truncated/base64 bodies don't parse, so they stay text. An empty body with no notes shows muted `No response body` instead (no toolbar); with a note (e.g. `Body unavailable`) `BodyView` still renders. Expand all sits in the panel, not the tab bar: the tab bar can't know whether the lazily loaded body is JSON. Raw always text.

## Copy (`src/panel/copy.ts`, `src/panel/copy-button.tsx`, `src/panel/curl.ts`)

- `valueText(value)`: strings as-is, everything else `JSON.stringify(value, null, 2)`. `pairsText(pairs)`: `name = value` lines.
- Summary: every `Section` with `copy` shows a `CopyButton` (`aria-label` `Copy <title>`) right of its heading. Decoded sections copy `valueText` of their text or JSON; `Pairs` copy `pairsText` (Headers and Params/Cookies too); Tokens copy `valueText({ header, payload })`.
- Body and Raw: captioned `Copy` in the panel's `Toolbar` row (not the tab bar: it can't know the lazily loaded body). Body copies the displayed (pretty) text; Raw copies `rawRequest` + blank line + `rawResponse`, so `RawPanel` renders entirely inside `LoadedBody`.
- `copyToClipboard(text)`: `navigator.clipboard.writeText`, falling back (on rejection or a missing API: DevTools panel frames can block it) to a hidden fixed `textarea`, `select()`, `document.execCommand("copy")`, remove.
- `CopyButton(label, value, captioned?)`: an `IconButton` (copy icon; check icon while copied) whose `aria-label`/`title` (and caption, when `captioned`) read `Copied` for `COPIED_MS` (1500), then revert; timer cleared on cleanup. `IconButton` gained an optional visible `caption`.
- `createCopied()`: `[copied, copy(text)]`, the `COPIED_MS` timer shared by `CopyButton` and Copy as.
- Copy as (`CopyAs` in `detail.tsx`): text button at the right of the Summary title row (`aria-haspopup="menu"`, `aria-expanded`), reads `Copied` for `COPIED_MS` after a copy. Opens a `role="menu"` popover (Schemas popover style) with `menuitem`s `cURL`, `fetch`; picking one copies and closes. Not rendered for sockets. Not redacted (your own replay).
  - Kept headers (`keptHeaders`): request headers minus `:`-prefixed pseudo-headers and `content-length`, `accept-encoding`, `connection`, `host` (case-insensitive; set by the transport).
  - `toCurl(entry)`: Chrome's Copy as cURL (bash) layout, parts joined by ` \` + newline + 2 spaces: `curl '<url>'`, `-X '<METHOD>'` unless implied (GET without body, POST with body), `-H '<name>: <value>'` per kept header, `--data-raw '<body>'`. `'` escaped as `'\''`.
  - `toFetch(entry)`: `await fetch(<JSON url>, <JSON options, 2-space>)`, options `{ method, headers, body? }`; headers an object (later duplicate wins); body omitted when absent. JSON keeps escaping valid.
  - Binary request bodies are written as their text (as in Raw); no `--data-binary`.

## HAR export (`src/panel/har.ts`, `src/panel/redact.ts`, `src/panel/download.ts`, `src/panel/footer.tsx`)

- Popover (`data-export`, Schemas popover style, column): semibold `Export <count(n, "request")>`, a `Redact secrets` checkbox (checked by default, `redact` signal in `Footer`, not persisted), `Download` (disabled at 0). Download calls `onExportHar(redact)`, awaits it, then closes.
- `exportHar` (`App`): `visible()` sorted by `startedAt` (oldest first, whatever the list order), each `getBody()` awaited (rejection gives `undefined`), `toHar(entries, bodies, version)` (`version` from `package.json`), `JSON.stringify(har, null, 2)`, `download(text, harFileName(entries, new Date()))`. Filters scope the export.
- `toHar` (pure): HAR 1.2 `log` with `creator { name: "SnapQL", version }`, `pages: []`. Per entry: ISO `startedDateTime`, `time`, `cache: {}`; `request` (`httpVersion` falls back to `HTTP/1.1`, cookies/headers/queryString from `exchange`, `postData` = `requestBody` when present, `headersSize -1`, `bodySize` = request text length or 0); `response` (`content { size, mimeType, text?, encoding? }`: size = decoded bytes via `base64Bytes` or text length, 0 without a body; `encoding: "base64"` kept for binary; no `text` when the body failed; `redirectURL ""`, `headersSize -1`, `bodySize` = `exchange.size`); `timings` with `send`/`wait`/`receive` clamped to 0 (HAR requires non-negative).
- Sockets: `_resourceType: "websocket"`, `_webSocketMessages` `{ type: send|receive, time (seconds), opcode 1 text / 2 binary, data (text or base64) }`, Chrome's layout.
- `redactHar(har)` (`src/panel/redact.ts`, pure, returns copies): value becomes `[redacted]` for
  - headers named `authorization`, `proxy-authorization`, `cookie`, `set-cookie`, or matching `SECRET` (`/token|secret|key|auth|session|csrf|password/i`); pseudo-headers (`:`-prefixed) skip the name rule (`:authority` matches `auth`);
  - every request and response cookie (the Cookie/Set-Cookie headers are always redacted, so the parsed lists would leak the same values);
  - `queryString` entries named like `SECRET`, and the URL rewritten pair by pair on the raw search (other params keep their encoding);
  - bodies (`postData.text`, non-base64 `content.text`, opcode-1 frames) via `redactText`: JSON object/array gets every `SECRET` key at any depth redacted, re-serialized compactly; else form-urlencoded mimes get field pairs redacted like the query;
  - JWTs anywhere left (URL, header/query values, bodies, frames): `/[\w-]+\.[\w-]+\.[\w-]*/g` candidates confirmed by `decodeJwt` (`values.ts`), so dotted text like `127.0.0.1` survives.
  - Untouched: base64 bodies, binary frames, multipart parts other than JWTs.
- `harFileName(entries, now)`: `snapql-<hostname of first entry>-<yyyymmdd>-<hhmmss>.har`, local time; no host part when empty. Hostname, not host: no `:` in file names.
- `download(text, name)`: `Blob` (`application/json`) object URL on a detached `<a download>`, `click()`, revoked next tick. No downloads permission, no `chrome.*`.

## Values (`src/panel/values.ts`)

- Pure helpers for header, cookie and param values; `decodeBase64` (UTF-8) lives here and is shared with `body.ts`.
- `decodeJwt(value)`: three base64url segments (`[\w-]`; signature may be empty), header and payload must decode to plain JSON objects and the header needs a string `alg`; returns `{ header, payload, expires? }` with `expires` = `exp` as ISO. Anything else `undefined`. Never verified.
- `findTokens(exchange)`: JWTs in order from `Authorization: Bearer` (case-insensitive), request cookies (`cookie <name>`), response cookies (`set-cookie <name>`), query params (`query <name>`); non-JWT values skipped.
- `decodeValue(value)`: first match of: JWT (payload as pretty JSON); percent-decoded text (raw kept if malformed) that parses to a JSON object/array (pretty JSON); percent-decoded text when it differs from the raw value; else `undefined`.
- `Pairs` with `decode` (Headers, Params/Cookies) shows `decodeValue` as a muted `whitespace-pre-wrap` line under the raw value; Summary rows don't decode.
- Summary `Tokens` section (after decoded data, before Response), only when tokens exist: `<source> · unverified`, `expires <iso>` when present, `header` and `payload` as `JsonTree`s.

## Body (`src/panel/body.ts`)

- `LoadedBody` (used by Body and Raw) renders notes, then its `children(text, formatted)`; it mounts only while its tab is active and runs `createResource(entry, loadBody)`, so bodies load on demand. Body uses `pretty: true`; Raw uses `formatBody`'s `{ pretty: false }` (truncation and base64 note still apply). The fetcher is wrapped because `createResource` passes its own info object as a second argument. `loadBody` and `ResponseGroup` are the panel's only `getBody()` callers; `getBody` itself memoizes, so revisiting the tab does not refetch.
- `formatBody(body, { pretty, mimeType })`: `{ text, notes, view? }`. `loadBody` passes `entry.mimeType`.
  - base64 with a text-like mime (`text/*`, `multipart/mixed`, `/json`, `+json`, contains `xml` or `javascript`): decoded as UTF-8 first, then treated as text (limit counts decoded chars). Chrome already sends `multipart/mixed` (incremental GraphQL) as text; the rule covers browsers that report it as base64.
  - Over `BODY_LIMIT` (1024 * 1024 characters): first `BODY_LIMIT` chars, note `Truncated: showing 1 MB of <n> characters`, never parsed. Not applied to `image`/`font` views, which render rather than parse.
  - Other `base64`: note `base64-encoded, <n> bytes` (decoded size) plus raw base64; never parsed.
  - `view` (Body tab only; Raw ignores it): `image` for base64 `image/png`, `jpeg`, `gif`, `webp`, `avif`, `x-icon`, `vnd.microsoft.icon`, and `image/svg+xml` in either encoding (text = SVG source); `font` for base64 `font/woff2`, `font/woff`, `font/ttf`, `font/otf`, `application/font-woff`; `hex` for any other base64.
- Body tab views (`BodyView` in `detail.tsx`): `image`: `<img src={imageSrc(text, mime)}>` (`data:<mime>;base64,` or, for SVG, `data:image/svg+xml;charset=utf-8,` + URI-encoded source), caption `<w> × <h> px · <size>` on load or `image failed to load`, SVG source below. `font`: `FontFace("snapql-font-<id>", bytes)` loaded and added to `document.fonts`, then `The quick brown fox jumps over the lazy dog 0123456789` at 12, 18 and 28 px, or `font failed to load`. `hex`: `hexDump` (64 KB cap, see Binary frames). Copy copies the text: base64 for binary views, source for SVG.
  - Otherwise: pretty JSON if it parses, else `prettyXml` (from `src/decoders/xml.ts`; balanced XML indented, anything else, including HTML, as-is). Detection is by parse only; `mimeType` is used only for base64.
- Failed fetch: `{ text: "", notes: ["Body unavailable: <message>"] }`.
- Chrome reports some text responses as base64 (e.g. no `content-type`); text-like ones are decoded above, the rest stay a note. The e2e server sends `application/json` for `/graphql`.

## Themes (`src/panel/themes.ts`, `src/panel/index.css`, `src/panel/main.tsx`)

- Themes are data: `Theme = { id, name, kind, colors: Record<ColorToken, string> }`, tokens `bg, fg, muted, border, selected, error, surface, accent, success, syntax-key, syntax-string, syntax-number`. Ships `devtools-light`, `devtools-dark`.
  - `bg`, `fg`, `selected`, `error` and dark `muted` copied from the DevTools document's `--sys-color-*` variables (source noted in the file).
  - SnapQL's own: `border` (softer than DevTools' divider: dark `#3d3d3d`, light `#e3e3e3`), light `muted` `#5f6368` (DevTools' `#757575` is 4.14:1 on `surface`), `surface` (code blocks), `accent` (active tab underline), `success`, `syntax-*` (JSON/XML colors).
  - `themes.test.ts` checks every text token (`fg`, `muted`, `error`, `success`, `accent`, `syntax-*`) is at least 4.5:1 on `bg` and `surface`. Dark `muted` on `selected` is 2.9:1, so selected rows must not rely on `muted`.
- `defaultTheme(kind)` picks by DevTools kind; this is "auto" for a future VS Code-style picker (multiple light/dark themes, persisted choice). Adding a theme is one entry in `themes`.
- `main.tsx` `applyTheme(theme)`: sets `themeVars(theme)` (`--theme-<token>`) on `<html>`, plus `data-theme=<id>`, `data-theme-kind=<kind>` and `color-scheme: <kind>` (so native scrollbars and form controls match; without it they stay light).
- `index.css` `@theme inline` maps Tailwind colors (`bg-bg`, `text-fg`, `border-border`, ...) to `--theme-*`. Components use tokens only, never a theme name. Biome needs `css.parser.tailwindDirectives` for this.
- Kind source: `getTheme()` (`themeName === "dark"`) at load; `onThemeChanged` in Firefox only. Chrome has no theme event, and its panel iframe's `prefers-color-scheme` flips during load (observed in e2e), so it can't stand in for one: Chrome keeps the load-time theme until the panel reopens.

## Schemas (`src/panel/schemas.ts`, `src/panel/schema-picker.tsx`, `src/panel/binary-frames.ts`, `src/panel/hex-dump.ts`)

- `createSchemas(storage, compile)` (created in `main.tsx` with `localStorage` and a dynamic import of `parseProto`): `files()` (names), `schema()`, `error()`, async `add(files)` (same name replaces) and `remove(name)`. Both recompile every file; on success state, `localStorage["snapql.schemas"]` (`{ files, schema }`) and `error()` are updated, on failure only `error()` (`<file>:<line>: <reason>`), so a failing file is never stored. Startup reads the stored compiled schema without loading the parser. Storage access is wrapped: unavailable storage means an empty, unpersisted store.
- `SchemaPicker` (`[data-schemas]`, absolute above the footer): `Add .proto files` (hidden `<input type=file multiple accept=".proto">`, read with `file.text()`), one row per file with `Remove <name>`, the error line.
- Summary: `useSchemaReaders` finds `schema().methods[path]` for a `grpc-web` entry, imports the `proto-schema` chunk and builds `messageReader`s; request data becomes `grpcRequestData(requestBody, input)` and the Response group decodes with `grpcResponse(body, headers, output)`. Rows captured before loading a schema get names at once; removing it reverts (a resource keeps its last value, so the readers are gated on the method still existing).
